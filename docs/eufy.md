# Sonnette Eufy

L’onglet Entrée utilise un service Node.js local (`npm run eufy:serve`, démarré aussi par `npm run dev`) avec `@mega-yfue/eufy-sdk` 0.4.0. Node 24.5 minimum est nécessaire. Le service écoute uniquement sur 127.0.0.1:8767, et Vite relaie `/api/eufy`.

La T8210C et sa HomeBase 2 (T8010) ont été validées avec une connexion réelle : modèle, base, batterie à 100 %, flux H.264/AAC et décodage effectif dans le navigateur en 2048 × 1536. L’interface prépare la connexion Eufy, le code de vérification et le CAPTCHA lorsque le fournisseur les exige. Le mot de passe est effacé du champ dès l’envoi. Il reste temporairement en mémoire du SDK pendant les étapes de connexion (expiration dix minutes), puis est vidé ; il n’est jamais écrit sur disque. La session fournisseur est conservée dans `.eufy-data/`, exclu de Git et interdit au serveur de fichiers Vite, avec dossier 0700 et fichiers 0600. Chaque navigateur possède un cookie HttpOnly SameSite Strict ; les POST vérifient leur origine et un en-tête spécifique. Aucun jeton Eufy n’est renvoyé au navigateur.

Une fois connecté, le service utilise les capacités déclarées pour lire le nom, le modèle, la base associée et la batterie. Les prochains événements `doorbellPress`, `motion` et `personDetected` sont conservés en mémoire (cinquante maximum), avec l’heure de réception. Il ne s’agit pas de l’historique de la HomeBase. La vue image utilise uniquement `snapshotStored()` : elle n’ouvre pas de flux et n’éveille pas volontairement la caméra. Une absence d’image est affichée explicitement. Le bouton Voir en direct lit des fragments MP4/CMAF du SDK via un endpoint authentifié, sans ffmpeg et sans enregistrement sur disque. Le navigateur utilise MediaSource et le codec H.264 déclaré par le flux. Le direct est limité à une minute, s’arrête à la fermeture de la vue ou lorsque la page devient masquée, et peut être relancé à la demande. Le serveur remplace une lecture précédente de la même session et libère son consommateur. Aucun changement de mode, sirène, micro ni réglage de sécurité n’est proposé.

La connexion au compte Eufy nécessite Internet ; cette intégration ne prétend pas être entièrement locale. Le compte est interrogé une fois par minute au maximum lorsqu’un navigateur consulte le service. Le SDK gère ses canaux d’événements, avec un rafraîchissement cloud de dix minutes. Sans mot de passe conservé, une session expirée demande une reconnexion explicite. Une erreur de lecture conserve les valeurs précédentes en les signalant.

Références : https://github.com/mega-yfue/eufy-sdk et https://mega-yfue.github.io/getting-started.

## Limite actuelle des alertes

Sur ce compte, Eufy refuse l’enregistrement push avec le code 10003. La connexion du canal FCM à elle seule ne garantit donc pas la réception d’événements. Le service le signale explicitement, même si la liaison P2P HomeBase et la vidéo fonctionnent. Un repli limité aux mêmes appels legacy eufySecurity déjà utilisés par le SDK est tenté lorsque son premier endpoint mega échoue ; aucune permission ou validation TLS n’est contournée. Les identifiants FCM sont conservés dans un fichier privé séparé pour éviter de recréer une identité à chaque redémarrage. Le test d’une sonnerie physique reste à effectuer : le propriétaire n’était pas disponible. L’ouverture automatique à la sonnerie n’est pas activée.
